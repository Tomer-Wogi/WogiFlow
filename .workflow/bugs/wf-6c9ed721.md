## Bug Summary

Two issues surfaced during full-suite verification of the 5 gate-bug fixes:

1. **Phase-gate test isolation (`tests/flow-hooks-phase-gate.test.js`)** — the CLI-spawn test added in wf-88a08fd4 wrote to the live `.workflow/state/workflow-phase.json` and raced parallel tests in the same suite, intermittently failing with `phase: 'idle'` (expected `'routing'`) under `npm test`. The test passed in isolation but failed under `node --test` parallelism.

2. **Standards-checker file-shape tolerance (`scripts/flow-standards-gate.js`)** — `runTaskStandardsCheck` documents `files` as `Object[{path, content}]` but is called from `scripts/flow-done-gates.js:421` with the `string[]` result of `ctx.getModifiedFiles()`. Calling `files.map(f => f.path)` then yields `[undefined, undefined, ...]`, which downstream `.includes()` on undefined throws as `Cannot read properties of undefined (reading 'includes')`. The error is swallowed by the caller's try/catch and surfaces as `standardsCompliance (checker error — degraded to manual check: ...)` warning on every `flow done`. Pre-existing; not introduced by this batch but discovered during it.

## Reproduction

**1.** `npm test` (full suite). The phase-gate test would fail intermittently under parallelism (`ERR_ASSERTION: phase: 'idle' !== 'routing'`).

**2.** Any `flow done <taskId>` would emit `standardsCompliance (checker error...)` warning. Reproducible directly:
```bash
node -e "require('./scripts/flow-standards-gate.js').runTaskStandardsCheck({type:'bug'}, ['some/file.js'])"
```
Pre-fix: throws `Cannot read properties of undefined (reading 'includes')` deep inside `inferTaskType`.

## Root Cause

1. **Test isolation**: I wrote the test (wf-88a08fd4) using the live state file with snapshot/restore, mirroring the existing pattern in `tests/flow-hooks-phase-gate.test.js`. That pattern works for in-process tests but not for CLI-spawn tests under `node --test` parallelism — other tests in the same file (and parallel files) race on the same `workflow-phase.json`.

2. **Standards-checker shape**: caller/callee impedance mismatch. `getModifiedFiles()` in `flow-done.js` returns `string[]` (file paths from `git status --porcelain`). `runTaskStandardsCheck()` documents `Object[]` shape. Has been silently degrading since both files existed.

## Fix Applied

### File `tests/flow-hooks-phase-gate.test.js`
- Rewrote the wf-88a08fd4 CLI-spawn test to use an isolated `os.tmpdir()` project.
- Sets both `WOGI_PROJECT_ROOT` (read by `flow-paths.js`) and `WOGIFLOW_PROJECT_ROOT` (read by `bin/flow`) env vars to the tmp dir.
- Reads the state file BEFORE the `finally`-block cleanup so the assertion is reliable.

### File `scripts/flow-standards-gate.js`
- Added defensive normalization at the top of `runTaskStandardsCheck`:
  - `files` becomes `[]` if not an array
  - Strings are wrapped into `{path, content: undefined}`
  - Entries without a valid `path` are filtered out
- Downstream content-dependent checks already skip undefined content (`if (!file.content) continue;`), so this degradation is graceful.
