# Bug: Invalid hook keys in Claude Code settings after WogiFlow setup

**ID**: wf-3f291f2d
**Status**: Fixed
**Priority**: P1
**Severity**: High
**Discovered from**: User report (Anton)
**Created**: 2026-02-24

## Summary

WogiFlow generates 4 invalid hook keys (Setup, ConfigChange, TaskCompleted, TeammateIdle) in `.claude/settings.local.json` that Claude Code rejects with schema validation errors. This blocks fresh installations completely — Claude Code refuses to load the configuration file.

## Reproduction

### Steps to Reproduce
1. Create a new project directory
2. Run `npm install wogiflow`
3. Run `npx flow init` or `npx flow onboard`
4. Launch Claude Code in the project
5. Observe validation errors in Claude Code output

### Expected Behavior
Claude Code loads the generated settings without errors. Only officially supported hook events are registered.

### Actual Behavior
Claude Code rejects the settings file with schema validation errors:
```
/path/to/project/.claude/settings.json
  └ hooks
    ├ ConfigChange: Invalid key in record
    ├ Setup: Invalid key in record
    ├ TaskCompleted: Invalid key in record
    └ TeammateIdle: Invalid key in record
```

### Environment
- WogiFlow: 1.5.11
- Claude Code: Latest (user's installation)
- Node.js: Any

## Root Cause Analysis

### What Went Wrong
The `generateConfig()` method in `scripts/hooks/adapters/claude-code.js` (lines 491-637) registers 10+ hook events, but Claude Code only supports 6 official hook events:

**Valid**: SessionStart, PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionEnd

**Invalid** (registered unconditionally by WogiFlow):
- `Setup` (line 507-515) — claimed "Claude Code 2.1.10+" but not in official spec
- `TaskCompleted` (line 582-590) — claimed "Claude Code 2.1.33+" but not validated
- `TeammateIdle` (line 593-601) — claimed "Claude Code 2.1.33+" but not validated
- `ConfigChange` (line 604-612) — claimed "latest" but not validated

The CLAUDE_CODE_EVENTS array (lines 41-56) lists these as supported without validation against the actual Claude Code schema. Also potentially invalid: `SubagentStop`, `Notification`, `WorktreeCreate`, `WorktreeRemove`.

### Why Did This Happen
- [x] Speculative implementation — hooks were added based on assumed future Claude Code support
- [x] No validation layer — hook names are not validated against Claude Code's accepted list
- [x] No version gating — hooks are registered unconditionally regardless of Claude Code version

## Fix Approach

**Chosen approach: Remove invalid hooks from generateConfig()**

1. Remove Setup, TaskCompleted, TeammateIdle, ConfigChange from the `generateConfig()` method
2. Remove SubagentStop, Notification from `CLAUDE_CODE_EVENTS` if also invalid
3. Keep WorktreeCreate/WorktreeRemove (these are documented in current Claude Code)
4. Add a `VALID_HOOK_EVENTS` allowlist that filters before writing to settings
5. Keep the entry scripts (they don't hurt) but don't register them

## Acceptance Criteria

### Scenario 1: Fresh install generates only valid hooks
Given a fresh project with WogiFlow installed
When the settings are generated via `generateConfig()`
Then only valid hook events (SessionStart, PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionEnd) are present in the hooks configuration

### Scenario 2: Existing functionality of valid hooks preserved
Given a project with WogiFlow hooks enabled
When hooks fire during a Claude Code session
Then SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, SessionEnd all function correctly

### Scenario 3: No schema validation errors
Given a freshly generated settings file
When Claude Code loads the configuration
Then zero validation errors appear for hook keys

## Prevention & Learning
- Add a VALID_HOOK_EVENTS allowlist constant that filters hook registration
- Future hooks should only be added after verification against Claude Code's published schema
- Add a config validation step in the health check to flag invalid hook keys
