# wf-12271e82: Research-required gate false-positives on the word "recommend"

**Created**: 2026-05-11
**Status**: Open
**Severity**: Medium
**Priority**: P1
**Tags**: #bug #research-required-gate #classifier
**Discovered From**: external session (wogiflow-cli build, 2026-05-10)
**Discovered During**: cross-project integration

## Bug Summary

The research-required gate continues to block (claiming insufficient evidence) even after the assistant has made multiple Read calls and received research-agent reports. The trigger word appears to be "recommend" appearing anywhere in user-visible output — the classifier marks the turn as a recommendation that requires evidence, but the evidence-counter doesn't credit reads against the trigger.

## Reproduction

### Steps to Reproduce
1. Have an active session in a WogiFlow project.
2. Read 3+ files from evidence paths (`.workflow/state/`, `lib/`, `scripts/`, etc.).
3. Invoke a research sub-agent that returns a report.
4. Produce any assistant turn that contains the word "recommend".
5. Observe the Stop hook re-prompt with `{ continue: true, stopReason: "..." }` saying more evidence is needed.

### Expected Behavior
After ≥2 Reads against evidence paths, the gate should pass — regardless of whether the response contains the word "recommend".

### Actual Behavior
Gate keeps blocking. The word "recommend" appears to be the trigger.

### Environment
- WogiFlow: this repo, v2.30.1
- Reported on npm `wogiflow`: latest as of 2026-05-10

---

## Root Cause Analysis

### What Went Wrong?
Likely two-layer issue:
1. The classifier (`scripts/hooks/core/research-required-classifier.js`) marks turns containing "recommend" as diagnostic with `requiredEvidence: 2`.
2. The Stop-hook gate (`scripts/hooks/core/research-required-gate.js`) counts evidence reads but may not credit them correctly — possibly only counts reads AFTER the marker is set, missing reads from earlier in the turn that informed the recommendation.

### Why Did This Happen?
- [x] Classifier over-triggers on a common verb
- [x] Evidence-counter race: marker set late in turn, prior reads not counted
- [x] No allowlist for explicit research-agent output: research-agent reports should count as compounded evidence

### Source of the Problem
- **Logic gap**: "recommend" is a Tier-2 (Domain) marker per CLAUDE.md's research-reasoning gate, but THIS gate (research-required) is supposed to fire on diagnostic prompts, not recommendations. The two gates may be conflated.

---

## Fix Approaches

### Approach 1: tighten the classifier (Recommended)
**Description**: "recommend" alone is not enough. Require co-occurring diagnostic markers (e.g., "why", "should I", "did you fix", "is this correct"). Pure recommendations without a question shouldn't trigger the research-required gate.
**Pros**: Targets the over-trigger directly.
**Cons**: May miss some legitimate diagnostic turns.
**Files affected**: `scripts/hooks/core/research-required-classifier.js`.

### Approach 2: credit research-agent output as evidence
**Description**: When a research sub-agent returns, count its return as N evidence units (N = number of files cited in its output).
**Pros**: Acknowledges that delegated research is real evidence.
**Cons**: Detection is heuristic.

### Approach 3: window the evidence count across the whole turn
**Description**: Count all Reads in the turn, not just post-marker.
**Pros**: Simple.
**Cons**: Doesn't fix the over-trigger, just the false-block.

### Chosen Approach
Approach 1, plus Approach 3 as a safety net.

## Acceptance Criteria

### Scenario 1: "recommend" alone does not trigger the gate
**Given** an assistant turn that says "I recommend X based on the code I've read"
**When** the turn ends
**Then** the gate does NOT mark the turn as research-required.

### Scenario 2: diagnostic + "recommend" still triggers
**Given** a user prompt like "why did this break? what do you recommend?"
**When** the turn fires
**Then** the gate fires (this is a real diagnostic).

### Scenario 3: evidence counts include the whole turn
**Given** the gate fires legitimately
**When** the assistant made ≥2 Reads earlier in the turn
**Then** those reads count toward the threshold.
