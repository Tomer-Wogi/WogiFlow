# wf-88a08fd4: flow-phase.js transition CLI silently no-ops

**Created**: 2026-05-11
**Status**: Open
**Severity**: Medium
**Priority**: P1
**Tags**: #bug #flow-phase #state-writer
**Discovered From**: external session (wogiflow-cli build, 2026-05-10)
**Discovered During**: cross-project integration

## Bug Summary

`node scripts/flow-phase.js transition <from> <to> <taskId>` returns exit 0 with no output and does NOT update `workflow-phase.json`. Tested across multiple phase pairs; the file stays at its original phase. Users (and agents) silently get the wrong state, then downstream gates that depend on phase misfire.

## Reproduction

### Steps to Reproduce
1. With `.workflow/state/workflow-phase.json` at `{ phase: "idle" }`:
2. Run `node scripts/flow-phase.js transition idle routing wf-XXXXXXXX`.
3. Observe exit code 0, empty stdout, empty stderr.
4. Re-read `.workflow/state/workflow-phase.json` — still `{ phase: "idle" }`.
5. Repeat for `exploring → validating → completing`. Same result every time.

### Expected Behavior
`workflow-phase.json` is updated to the new phase atomically. Some confirmation output is printed.

### Actual Behavior
Exit 0, no output, no state change. Workaround used: write `workflow-phase.json` directly via Edit/Write.

### Environment
- WogiFlow: this repo, v2.30.1
- Reported on npm `wogiflow`: latest as of 2026-05-10

## Root Cause Analysis

### What Went Wrong?
The `transition` subcommand in `scripts/flow-phase.js` is wired but either (a) imports a stale state-writer, (b) writes to a path that's not the canonical `workflow-phase.json`, or (c) silently catches an error and returns 0.

### Why Did This Happen?
- [x] Logic error in implementation — silent catch + exit 0
- [x] Incorrect assumption about inputs/state — possibly using an outdated state-file path constant

### Source of the Problem
- **Logic gap**: error handling swallows the failure and returns success. Per `security-patterns.md` §1, file writes need explicit error surfacing.

---

## Fix Approaches

### Approach 1: trace the writer and unify with the read path (Recommended)
**Description**: Find every reader of `workflow-phase.json` in the codebase. Whatever path/module they use is canonical. Make `flow-phase.js transition` write through that exact module. Surface errors instead of swallowing.
**Pros**: Fixes both the silent-failure and the multi-source-of-truth risk.
**Cons**: May reveal additional drift.
**Files affected**: `scripts/flow-phase.js`, possibly `scripts/flow-utils.js` or `scripts/flow-io.js`.

### Approach 2: minimal "make it write" fix
**Description**: Just patch the write path inline.
**Pros**: Smallest change.
**Cons**: Doesn't address why it broke; may break again.

### Chosen Approach
Approach 1.

## Acceptance Criteria

### Scenario 1: transition updates state
**Given** `workflow-phase.json` shows `idle`
**When** `flow-phase.js transition idle routing wf-XXXXXXXX` is invoked
**Then** the file is rewritten to `{ phase: "routing", taskId: "wf-XXXXXXXX" }` (or equivalent schema), AND stdout reports the transition.

### Scenario 2: failure is loud
**Given** a write fails (read-only filesystem, permission error, schema validation failure)
**When** `flow-phase.js transition` is invoked
**Then** stderr describes the failure and exit code is non-zero.

### Scenario 3: invalid transition is rejected
**Given** an illegal transition (e.g., `idle → completing` if disallowed)
**When** the CLI is invoked
**Then** it rejects with a clear error and does not corrupt state.
