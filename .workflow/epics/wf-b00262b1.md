## 0. Why this exists

## 2. Architect Pass (manual IGR Stage 3, applied to this epic)

### Approach

Ship all 7 stages as a single cohesive feature gated behind `intentGroundedReasoning.enabled` (default false). Stages are added incrementally as separate stories under this epic, but each story's code is wrapped behind the master flag so partial-landing states are invisible to users. The dogfood plan is strict: wogi-flow itself is the first project to flip the flag on, then wogi-hub (owner's production-adjacent project), then v3.0 general release.

Stages are interdependent — they cannot be released as 7 independent features. Logic Adversary (Stage 4) needs intent artifacts from Stage 1 and Architect output from Stage 3. Intent Framing (Stage 2) needs session corrections from Stage 5. Completion Truth Gate (Stage 6) extends the existing evidence-tier framework from Step 3.58. Pipeline wiring (Stage 7) is the last step because it hooks everything into `/wogi-start`.

### Data model touchpoints
- **New state files** (created per-project): `product.md`, `domain-model.md`, `user-journeys.md`, `glossary.md`, `session-corrections.json`, `adversary-calibration.json`, `igr-bootstrap-state.json`
- **New per-task artifacts**: `.workflow/state/framing/{taskId}.md`, `.workflow/state/evidence-records/{taskId}.json`, `.workflow/plans/{taskId}.md`
- **New WogiFlow package files**: 6 scripts, 3 agent personas, 4 templates, 1 rubric, 1 docs page, 1 new slash command, schema changes
- **Modified files**: `wogi-start.md` command file, `explore-agents.md` docs, `flow-prompt-composer.js`, `flow-context-orchestrator.js`, `flow-eval.js`, `config.schema.json`, `lib/installer.js`

### Net-new concepts introduced
Every one of these is defined in the approved spec — none are silent additions:
- Intent artifact · Framing artifact · Plan artifact · Logic Constitution · Principle verdict (PASS/CONCERN/FAIL) · Session correction · Evidence record · Trap-zone ambiguity

### Alternatives considered and rejected

| Alternative | Rejected because |
|-------------|------------------|
| Ship one stage per minor version over 7 releases | Stages are interdependent. Mid-state (e.g., Framing but no Adversary) creates degraded UX that's hard to reason about and test. |
| Ship default-on in first release | Owner's approved rollout plan (spec §9) specifies opt-in first. Also violates "do not change default behavior of existing projects without notice." |
| Implement stages in forward order (1→7) sequentially | Stage 4 (Adversary) is the highest-leverage and should be dogfoodable earliest. Ordering must be dependency-driven, not numeric. |
| Implement everything in a single megaPR | Too large to review safely. Loses the dogfood benefit of exercising earlier stages while implementing later ones. |
| Use the existing skeptical evaluator (Step 3.56) for Adversary | Different target (post-code vs pre-code), different inputs (diff vs plan), different rubric. Reuse would force one agent to do two jobs poorly. |

### Risks
See §6.

### Reversibility
- Feature flag: `intentGroundedReasoning.enabled` = false restores prior behavior completely.
- All new files are additive (no deletions of existing files).
- All pipeline modifications are wrapped in `if (config.intentGroundedReasoning.enabled)` guards.
- Rollback procedure: set flag to false in `config.json` → next `/wogi-start` behaves as v2.x.
- No irreversible operations at any stage.

### Dependencies on other systems/tasks
- No external dependencies.
- Internal consumer: wogiflow-cloud — verified unaffected (no exported-function changes, no state-file-format changes to existing files, no hook-interface changes).
- Blocks nothing. Blocked by nothing.

### Hook architecture compliance (explicit)

Stage 5's PostUserMessage correction-detector hook **must** follow the three-layer entry/core/adapter pattern per `self-maintenance.md` §2:
- `scripts/hooks/entry/claude-code/session-corrections.js` (CLI-specific entry)
- `scripts/hooks/core/session-corrections.js` (CLI-agnostic logic)
- `scripts/hooks/adapters/claude-code.js` (transforms result)
- Registration in `.claude/settings.local.json`
- Config toggle in `.workflow/config.json` under `intentGroundedReasoning.sessionCorrections`

### CLAUDE.md template pipeline (explicit)

Any CLAUDE.md change for IGR documentation **must** go through the template system per `self-maintenance.md` §1:
- Edit `.workflow/templates/claude-md.hbs` or a new partial in `.workflow/templates/partials/`
- Regenerate with `node scripts/flow-bridge.js sync claude-code`
- Never edit CLAUDE.md directly — any such edit will be overwritten on next sync

Story 7 (Pipeline wiring + rollout) owns the CLAUDE.md partial addition.

### Edge cases and failure modes

Addresses Adversary Round-1 P8 FAIL finding. The plan must specify behavior for:

| Scenario | Behavior |
|----------|----------|
| **Adversary blocks after maxRounds** (overallVerdict=FAIL, round==maxRounds) | Task moves from `inProgress` to `blocked` array in `ready.json` with `blockReason: "adversary-max-rounds-fail"` and `lastAdversaryVerdict: .workflow/state/adversary-runs/{taskId}-r{N}.json`. Surface to user with the full verdict rendered. User can override and resume via `/wogi-start <taskId> --ignore-adversary` (explicit opt-out, tracked). |
| **Concurrent writes to `session-corrections.json`** | Use `acquireLock` from `flow-io.js` (existing machinery, 60s stale threshold). Appends are short — lock contention is rare. On lock-acquire failure, log a warn and drop the event rather than block user work. Telemetry records the drop. |
| **Background bootstrap failure** (Stage 1 Option C [2]) | Record failure in `igr-bootstrap-state.json`: `{ "lastAttempt": ISO, "lastAttemptResult": "failed", "lastAttemptError": "...", "retryCount": N }`. Next session offers retry; after 3 failures, fall back to Option [3] "skip for now" behavior. Telemetry records each attempt. |
| **Intent artifact drift / re-bootstrap trigger** | Extend `flow-knowledge-sync.js` (existing machinery) to check intent artifacts' content-hash against a recorded baseline in `knowledge-sync.json`. When drift exceeds the existing threshold, surface at `/wogi-session-end` ("X intent artifacts drifted from their last-reviewed state — refresh now?") rather than auto-re-bootstrap. User always opts in. |
| **Intent artifacts missing entirely** (first-run pre-bootstrap) | Adversary runs in degraded mode — principles 3, 4, 6, 9 SKIP with telemetry-recorded reason. Principles 1, 2, 5, 7, 8, 10 still fire. Provides ~60% coverage during the grace window before bootstrap completes. |
| **session-corrections.json corrupted** | `safeJsonParse` with empty-array fallback. Log a warn. Next session's detector re-creates the file. No task blockage. |
| **Rubric version mismatch** between recorded telemetry and current config | Telemetry preserves the original rubric version per event. Stats aggregation groups by `gateVersion` so rubric evolution is auditable. No runtime rejection. |

### Adversary false-positive handling (calibration signal)

Adversary Round-1 flagged wogi-hub as scope creep (P2 CONCERN) despite it being explicitly in approved spec §9 Phase B. Not a plan defect — a calibration defect. Promoted to `.workflow/state/adversary-calibration.json` under `_comment` for future rubric tuning: "reference the approved spec when reasoning about scope, not just the immediate framing artifact."

- False-completion incidents per 100 tasks: <3 (baseline ~30)
- Domain-confusion incidents per 100 tasks: <2 (baseline ~8)
- "ultrathink" keyword frequency in user messages: <10% (baseline 40%)
