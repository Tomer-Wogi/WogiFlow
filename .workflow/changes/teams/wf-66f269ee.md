## User Story

As a WogiFlow team admin, I want a marketplace where I can publish and discover templates, skills, and knowledge packs, so that teams can share reusable configurations.

## Description

Create the database schema and core CRUD API for marketplace listings. This is the data foundation that S2-S4 build on. Listings represent publishable packages (templates, skills, knowledge-packs) with metadata, versioning, and ownership.

## Acceptance Criteria

### AC1: Marketplace Schema (migration 014)
Given the database
When migration 014_marketplace.sql runs
Then tables are created:
- `marketplace_listings` (id, team_id, publisher_id, type ['template','skill','knowledge_pack'], name, slug, description, version, readme, tags JSONB, downloads INT DEFAULT 0, stars_avg NUMERIC DEFAULT 0, stars_count INT DEFAULT 0, verified BOOLEAN DEFAULT false, published BOOLEAN DEFAULT false, published_at, created_at, updated_at)
- `marketplace_versions` (id, listing_id, version, content JSONB, changelog, published_at, created_at)
- `marketplace_reviews` (id, listing_id, user_id, team_id, rating INT CHECK 1-5, body, created_at, updated_at)
- `marketplace_installs` (id, listing_id, version_id, team_id, installed_by, installed_at)
- Indexes on: listings(type, published), listings(slug UNIQUE), reviews(listing_id), installs(listing_id)

### AC2: Listings CRUD API
Given an authenticated team admin
When they call the listings API
Then these endpoints work:
- `POST /api/teams/:teamId/marketplace/listings` — Create draft listing
- `GET /api/teams/:teamId/marketplace/listings` — List own team's listings
- `GET /api/teams/:teamId/marketplace/listings/:id` — Get listing detail
- `PUT /api/teams/:teamId/marketplace/listings/:id` — Update listing
- `DELETE /api/teams/:teamId/marketplace/listings/:id` — Delete (soft) listing
- Only admin/owner can create/update/delete

### AC3: Version Management API
Given a listing
When the publisher creates a new version
Then:
- `POST /api/teams/:teamId/marketplace/listings/:id/versions` — Create version with content JSONB + changelog
- `GET /api/teams/:teamId/marketplace/listings/:id/versions` — List versions
- Content JSONB stores the serialized template/skill/knowledge-pack data
- Version string follows semver format (validated)

### AC4: Listing Validation
Given a listing creation/update request
When the data is submitted
Then validation ensures:
- Name: 3-100 chars, alphanumeric + hyphens + spaces
- Slug: auto-generated from name, unique across all listings
- Type: one of template, skill, knowledge_pack
- Version: valid semver
- Tags: array of strings, max 10, each max 30 chars
- Description: max 2000 chars
- Readme: max 50000 chars (markdown)
