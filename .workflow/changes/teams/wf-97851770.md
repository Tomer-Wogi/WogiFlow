## User Story

As a WogiFlow team admin, I want to apply for verified publisher status and publish marketplace packages, so that other teams can trust and use our contributions.

## Description

Add the publisher verification flow: teams apply for verified status, get reviewed (initially manual/admin), and once verified can publish listings with a verified badge. Also adds the publish/unpublish workflow for listings.

## Acceptance Criteria

### AC1: Publisher Application
Given a team admin
When they apply for publisher status
Then:
- `POST /api/teams/:teamId/marketplace/publisher/apply` — Submit application (body: { description, portfolioUrl?, contactEmail })
- Creates record in `marketplace_publishers` table (team_id, status='pending', applied_at)
- Status flow: pending → approved | rejected
- Only one active application per team

### AC2: Publisher Management (Admin)
Given a platform admin
When they review publisher applications
Then:
- `GET /api/admin/marketplace/publishers?status=pending` — List applications
- `PUT /api/admin/marketplace/publishers/:teamId` — Approve or reject (body: { status, reason? })
- On approve: set team's `marketplace_publishers.status = 'approved'`, `verified_at = NOW()`
- On reject: set status='rejected' with reason
- Audit log entry for every approval/rejection

### AC3: Publish/Unpublish Flow
Given a verified publisher team
When they publish a listing
Then:
- `POST /api/teams/:teamId/marketplace/listings/:id/publish` — Publish listing (requires at least 1 version)
- Sets `published = true`, `published_at = NOW()`
- Listing gets `verified = true` badge if publisher team is verified
- `POST /api/teams/:teamId/marketplace/listings/:id/unpublish` — Unpublish (soft-hide)
- Non-verified teams can still publish, but without verified badge

### AC4: Publisher Schema (migration 015)
Given the database
When migration 015 runs
Then:
- `marketplace_publishers` table: (team_id PK REFERENCES teams, status CHECK('pending','approved','rejected'), description, portfolio_url, contact_email, applied_at, verified_at, rejected_reason, updated_at)
