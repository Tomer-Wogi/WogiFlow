# [wf-917c85b7] Implement Video Methodologies: Prompt Capture, Correction Detection, and Bulk Loop


## User Story
**As a** WogiFlow user
**I want** the system to learn from my clarifications and corrections during task execution
**So that** the AI improves over time and I don't have to repeat myself

## Description
Based on research into Matt Maher's "do-work" pattern and Peter's Claudebot "self-configuring" pattern, this story implements three learning features:
1. **Prompt Iteration Capture** - Track all user prompts during tasks, identify refinements, and generate learning entries
2. **Real-Time Correction Detection** - Use Haiku to semantically detect when users correct the AI mid-conversation
3. **Bulk Loop Command** - Continuous work mode that processes captured ideas and ready tasks autonomously

These features enable WogiFlow to learn from user interactions without requiring explicit `/wogi-correct` invocations.

## Acceptance Criteria

### Scenario 1: Prompt capture during task execution
**Given** a task is in progress (durable session exists)
**When** the user submits a prompt via the user-prompt-submit hook
**Then** the prompt is captured to `.workflow/state/prompt-history.json`
**And** if the prompt matches refinement patterns (no, I meant, actually, etc.), it's flagged as a refinement
**And** refinement count is tracked in the task's history

### Scenario 2: Clarification learning on task completion
**Given** a task completes with refinementCount > 0
**When** `flow done` runs
**Then** a learning entry is generated in `.workflow/state/clarifications.md`
**And** the entry includes: initial request, refinement count, what finally worked
**And** the request-log entry includes refinement count (e.g., "Refinements: 2")

### Scenario 3: High-refinement pattern flagging
**Given** a task needed 3+ refinements to complete
**When** the task completes
**Then** the pattern is flagged in `feedback-patterns.md` for potential rule promotion
**And** the pattern includes the initial request and successful clarification

### Scenario 4: Semantic correction detection (optional - requires Haiku API)
**Given** ANTHROPIC_API_KEY is configured
**When** a user submits a message that semantically corrects the AI
**Then** the correction is detected using Haiku (semantic, not regex)
**And** the correction is queued in `.workflow/state/pending-corrections.json`
**And** corrections are shown for review at session end

### Scenario 5: Graceful degradation without API key
**Given** ANTHROPIC_API_KEY is NOT configured
**When** correction detection is attempted
**Then** the system falls back to regex-based detection
**And** no errors are thrown

### Scenario 6: Bulk loop continuous mode
**Given** tasks exist in ready.json or captures exist
**When** `/wogi-bulk-loop` is invoked
**Then** tasks are processed sequentially with all quality gates
**And** captured ideas (from /wogi-capture) are converted to stories
**And** the loop continues checking for new work until stopped or limit reached

### Scenario 7: Bulk loop YOLO mode
**Given** `--yolo` flag is passed to `/wogi-bulk-loop`
**When** tasks are processed
**Then** spec approval prompts are skipped (auto-approved)
**And** commit confirmations are skipped (auto-committed)
**But** quality gates (lint, typecheck, tests) are NOT skipped

### Scenario 8: Bulk loop safety mechanisms
**Given** the bulk loop is running
**When** context reaches 80%
**Then** auto-compact is triggered and loop continues
**When** 3 consecutive errors occur
**Then** the loop stops with error summary
**When** max iterations (default 100) is reached
**Then** the loop stops gracefully

## Technical Notes
- **Files to Create**:
  - `scripts/flow-prompt-capture.js` - Prompt history and refinement detection
  - `scripts/flow-correction-detector.js` - Semantic correction detection using Haiku
  - `scripts/flow-bulk-loop.js` - Continuous work loop implementation
  - `.claude/commands/wogi-bulk-loop.md` - Command documentation

- **Files to Modify**:
  - `scripts/hooks/entry/claude-code/user-prompt-submit.js` - Add prompt capture
  - `scripts/flow-done.js` - Add clarification entry generation
  - `scripts/flow-auto-learn.js` - Add high-refinement pattern flagging

- **State Files Created**:
  - `.workflow/state/prompt-history.json` - Full prompt history per task
  - `.workflow/state/clarifications.md` - Learning entries from refinements
  - `.workflow/state/pending-corrections.json` - Queued corrections for review

- **API**: Uses `flow-model-caller.js` for Haiku calls (existing)
- **Constraints**: Semantic detection is optional (graceful degradation without API key)
