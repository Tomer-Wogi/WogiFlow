# [wf-4c237257-08] E2-S3: Voice Answer Integration

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 2: Clarification System**

## User Story
**As a** user who prefers speaking over typing
**I want** to answer clarification questions via voice
**So that** I can provide detailed answers quickly

## Description
Integrate the existing voice-input system with the clarification loop, allowing users to speak their answers which are then transcribed and processed.

## Acceptance Criteria

### Scenario 1: Voice prompt
**Given** a clarification question is presented
**When** the user indicates voice mode (or it's configured as default)
**Then** Claude prompts: "You can speak your answer now, or type it"
**And** recording starts when user is ready

### Scenario 2: Voice transcription
**Given** user speaks their answer
**When** the recording completes
**Then** the answer is transcribed using configured provider
**And** the transcription is shown to user for verification

### Scenario 3: Transcription confirmation
**Given** transcription is shown
**When** user confirms it's correct
**Then** the answer is processed normally
**And** if incorrect, user can re-record or type correction

### Scenario 4: Mixed mode
**Given** clarification is in progress
**When** user provides answers
**Then** they can freely switch between voice and text
**And** both are processed identically

### Scenario 5: Long voice answers
**Given** user speaks for extended time (>30 seconds)
**When** processing the answer
**Then** the full answer is captured
**And** multiple questions may be answered in one recording

## Technical Notes
- **Integration**: Use existing `flow voice-input` system
- **Providers**: OpenAI Whisper, Groq, Local (from config)
- **Output**: Transcribed text fed into clarification loop

## Dependencies
- [wf-4c237257-07] Clarification loop must exist
- Existing voice-input system

## Scope
**S** - Integration with existing voice system
