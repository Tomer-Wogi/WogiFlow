# [wf-84923e2c] Phase 6: Team & Integrations

## User Story
**As a** team lead or developer on a multi-person team
**I want** visibility into team progress and integration with external tools
**So that** I can track work across the team and sync with existing project management tools

## Description
Phase 6 adds team collaboration features to Wogi Flow. This includes a web-based observability UI for viewing task progress and execution history, integration with Jira and Linear for syncing tasks from external project management tools, and a background sync daemon for keeping state consistent when multiple agents work on different branches.

## Acceptance Criteria

### Scenario 1: Team Observability Web UI - Basic Dashboard
**Given** a user has Wogi Flow installed with task history
**When** they run `flow team dashboard` or access the web UI
**Then** they can see a dashboard showing:
  - All recent runs with status (success/failure)
  - Per-step spans with inputs/outputs
  - Retry history and failure context
**And** the UI is served locally via HTTP

### Scenario 2: Team Observability - Team-wide View
**Given** multiple team members are using Wogi Flow
**When** they sync to the team backend
**Then** the dashboard shows team-wide task progress
**And** role-based access is enforced (admin, lead, member)

### Scenario 3: Jira Integration
**Given** a user has Jira credentials configured
**When** they run `flow external-tasks` or `flow jira list`
**Then** they see their assigned Jira tasks
**And** running `flow jira sync` creates stories in ready.json
**And** completed tasks can be synced back to Jira

### Scenario 4: Linear Integration
**Given** a user has Linear API key configured
**When** they run `flow linear list`
**Then** they see their assigned Linear issues
**And** running `flow linear sync` creates stories in ready.json
**And** completed tasks can be synced back to Linear

### Scenario 5: Background Sync Daemon
**Given** multiple agents work on different branches
**When** the sync daemon is running
**Then** it watches .workflow/state/ for changes
**And** syncs state on branch switch
**And** provides automatic cache invalidation
**And** maintains heartbeat monitoring

### Scenario 6: CLI Commands
**Given** Phase 6 features are implemented
**When** user runs relevant commands
**Then** all new commands work correctly:
  - `flow team dashboard` - Start web dashboard
  - `flow external-tasks` - List tasks from integrations
  - `flow jira list|sync|config` - Jira commands
  - `flow linear list|sync|config` - Linear commands
  - `flow sync-daemon start|stop|status` - Daemon management

## Technical Notes
- **Components to create**:
  - `flow-team-dashboard.js` - Local web server with dashboard UI
  - `flow-jira-integration.js` - Jira API client and sync logic
  - `flow-linear-integration.js` - Linear API client and sync logic
  - `flow-sync-daemon.js` - Background file watcher and sync
  - `public/dashboard/` - Static HTML/JS for dashboard UI
- **Dependencies**:
  - Phase 4 complete (Parallel Dispatch for multi-agent scenarios)
  - Existing team backend (already exists per roadmap)
- **Config structure**:
  ```json
  {
    "integrations": {
      "jira": {
        "enabled": false,
        "baseUrl": "https://company.atlassian.net",
        "projectKey": "PROJ",
        "apiToken": "{env:JIRA_API_TOKEN}"
      },
      "linear": {
        "enabled": false,
        "apiKey": "{env:LINEAR_API_KEY}",
        "teamId": null
      }
    },
    "syncDaemon": {
      "enabled": false,
      "watchPaths": [".workflow/state/"],
      "syncOnBranchSwitch": true,
      "heartbeatIntervalMs": 30000
    }
  }
  ```
