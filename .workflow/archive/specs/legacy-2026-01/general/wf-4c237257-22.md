# [wf-4c237257-22] E5-S4: Large Transcript Chunking

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 5: Multi-language & Persistence**

## User Story
**As a** user with very large transcripts (2+ hours)
**I want** them processed reliably
**So that** length doesn't cause processing failures or quality degradation

## Description
Implement chunking strategy for very large transcripts that exceed optimal processing size, ensuring quality is maintained across chunks and topics are properly merged.

## Acceptance Criteria

### Scenario 1: Chunk threshold detection
**Given** a transcript > 10,000 words
**When** size is assessed
**Then** chunking is triggered
**And** user is informed: "Large transcript detected. Processing in sections for best results."

### Scenario 2: Semantic chunking
**Given** chunking is needed
**When** splitting the transcript
**Then** chunks are split at natural boundaries (topic shifts, speaker changes)
**And** not mid-sentence or mid-thought
**And** some overlap is maintained for context

### Scenario 3: Per-chunk processing
**Given** transcript is chunked
**When** Pass 1-4 run
**Then** each chunk is processed independently
**And** topics are extracted per chunk
**And** progress is shown: "Processing section 2 of 5..."

### Scenario 4: Topic merging
**Given** chunks are processed
**When** merging results
**Then** topics that appear in multiple chunks are merged
**And** not duplicated
**And** statements from all chunks are associated correctly

### Scenario 5: Cross-chunk references
**Given** a statement in chunk 3 refers to something in chunk 1
**When** association runs
**Then** the reference is detected
**And** statement is associated with the correct topic

### Scenario 6: Verification across chunks
**Given** all chunks are processed and merged
**When** final verification runs
**Then** coverage is calculated across entire transcript
**And** no statements are lost at chunk boundaries

## Technical Notes
- **Chunk size**: ~5000 words with ~500 word overlap
- **Boundary detection**: Topic shifts, speaker changes, timestamps
- **Merging**: Semantic similarity for topic deduplication
- **Output**: Single unified topics.json and statement-map.json

## Dependencies
- [wf-4c237257-02] Topic extraction
- [wf-4c237257-03] Statement association

## Scope
**L** - Complex chunking and merging logic
