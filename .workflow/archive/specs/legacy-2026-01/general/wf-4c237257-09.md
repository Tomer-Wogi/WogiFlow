# [wf-4c237257-09] E2-S4: Clarification State Persistence

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 2: Clarification System**

## User Story
**As a** user who may need to pause clarification
**I want** my progress to be saved
**So that** I can resume without losing answers

## Description
Ensure all clarification state is persisted so users can close the chat, take a break, and resume exactly where they left off.

## Acceptance Criteria

### Scenario 1: State saved on each answer
**Given** user answers a clarification question
**When** the answer is processed
**Then** `clarifications.json` is immediately updated
**And** includes: question, answer, timestamp, linked statements

### Scenario 2: Resume after break
**Given** user closes chat mid-clarification
**When** user returns and continues
**Then** already-answered questions are not re-asked
**And** pending questions are presented

### Scenario 3: Progress indicator
**Given** clarification is in progress
**When** showing status
**Then** user sees "Clarification: 8 of 15 questions answered"
**And** progress is per-topic and overall

### Scenario 4: Answer history
**Given** user wants to review previous answers
**When** requested
**Then** all Q&A pairs are shown with timestamps
**And** user can modify previous answers if needed

### Scenario 5: Answer modification
**Given** user wants to change a previous answer
**When** they indicate the change
**Then** the old answer is superseded (not deleted)
**And** the new answer is used for story generation
**And** history shows both versions

## Technical Notes
- **State file**: `clarifications.json`
- **Structure**: Questions with answer history, timestamps, links
- **Recovery**: On session start, check for incomplete clarification

## Dependencies
- [wf-4c237257-07] Clarification loop must exist

## Scope
**S** - State persistence logic
