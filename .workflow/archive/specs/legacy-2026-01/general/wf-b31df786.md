# [wf-b31df786] Phase 2: Multi-Model Core - Task Analysis and Model Routing

## User Story
**As a** developer using Wogi Flow
**I want** intelligent model selection based on task analysis
**So that** tasks are routed to optimal models for quality and cost efficiency

## Description
Phase 2 builds on the model registry (Phase 1) to add intelligent multi-model routing. This includes a task analyzer that determines complexity/domains/languages, a model router with multiple strategies (quality-first, cost-optimized, learned), and a prompt fragment system for composable prompts per model/CLI.

## Acceptance Criteria

### Scenario 1: Task Analysis
**Given** a task with title, type, and description
**When** the task analyzer runs
**Then** it returns complexity (low/medium/high), domains, languages, and token estimate
**And** the analysis is saved for routing decisions

### Scenario 2: Model Selection - Quality First
**Given** a task analysis result
**When** routing strategy is "quality-first"
**Then** the system selects the highest-capability model matching requirements
**And** provides fallback and escalation options

### Scenario 3: Model Selection - Cost Optimized
**Given** a task analysis result
**When** routing strategy is "cost-optimized"
**Then** the system selects the cheapest model with required capabilities
**And** only escalates to higher tier on failure

### Scenario 4: Prompt Fragment Loading
**Given** prompt fragments in .workflow/prompts/fragments/
**When** fragments are loaded
**Then** each fragment has purpose, models, and cli tags
**And** fragments can be filtered by these tags

### Scenario 5: Prompt Composition
**Given** a task type and target model
**When** the prompt composer runs
**Then** it assembles fragments in correct order
**And** applies model-specific formatting

### Scenario 6: CLI Integration
**Given** the multi-model system is configured
**When** running "flow models recommend <task-type>"
**Then** it shows task analysis, model selection, and reasoning
