# [wf-4c237257-10] E3-S1: Adaptive Complexity Detection

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 3: Story Generation & Approval**

## User Story
**As a** user with varying transcript complexity
**I want** the output structure to match the scope
**So that** simple requests don't become overengineered and complex ones are properly organized

## Description
Implement logic to analyze the extracted topics and determine the appropriate output structure: Stories only, Phases with Stories, or Feature with Epics and Stories.

## Acceptance Criteria

### Scenario 1: Small scope detection
**Given** 1-3 topics with < 10 total statements
**When** complexity is assessed
**Then** output structure is "stories only"
**And** no phases or epics are created

### Scenario 2: Medium scope detection
**Given** 4-8 topics with 10-30 total statements
**When** complexity is assessed
**Then** output structure is "phases with stories"
**And** topics are grouped into 2-3 logical phases

### Scenario 3: Large scope detection
**Given** 8+ topics with 30+ total statements
**When** complexity is assessed
**Then** output structure is "feature with epics"
**And** topics are grouped into epics
**And** epics are organized into phases if needed

### Scenario 4: Manual override
**Given** any scope
**When** user specifies preferred structure
**Then** the user's preference is used
**And** topics are organized accordingly

### Scenario 5: Structure preview
**Given** complexity is assessed
**When** showing the result
**Then** user sees: "Based on 12 topics and 45 requirements, I'll create: 3 Phases with 12 Stories"
**And** user can approve or request different structure

## Technical Notes
- **Thresholds**: Configurable in config.json
- **Grouping logic**: Semantic similarity, dependencies, logical flow
- **Output**: Structure decision saved in digest state
