# [wf-4c237257-01] E1-S1: Skill Structure and State Management

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 1: Core Extraction Engine**

## User Story
**As a** developer implementing transcript digestion
**I want** a well-structured skill with proper state management
**So that** the multi-pass extraction can persist and recover state

## Description
Create the transcript-digestion skill structure following wogi-flow conventions. Set up the state directory structure for tracking digestion sessions, including transcript storage, topic tracking, statement mapping, and clarification logs.

## Acceptance Criteria

### Scenario 1: Skill structure created
**Given** the transcript-digestion skill doesn't exist
**When** the skill is initialized
**Then** `.claude/skills/transcript-digestion/skill.md` exists with proper metadata
**And** `commands/digest.md` defines the entry point
**And** `rules/extraction-rules.md` contains extraction guidelines
**And** `knowledge/patterns.md` and `knowledge/anti-patterns.md` exist

### Scenario 2: State directory initialized
**Given** a new digestion session starts
**When** the session is created
**Then** `.workflow/state/digests/active-digest.json` tracks the current session
**And** a unique digest folder is created: `.workflow/state/digests/[digest-id]/`
**And** the folder contains: `transcript.md`, `topics.json`, `statement-map.json`, `orphans.json`, `clarifications.json`

### Scenario 3: Session recovery
**Given** a digestion session was interrupted
**When** the user returns
**Then** `active-digest.json` indicates there's an active session
**And** all state files are intact and readable
**And** the session can resume from where it left off

### Scenario 4: Config integration
**Given** the skill is installed
**When** checking configuration
**Then** `transcriptDigestion` section exists in `config.json`
**And** all options are documented (autoTriggerThreshold, clarificationStyle, etc.)
