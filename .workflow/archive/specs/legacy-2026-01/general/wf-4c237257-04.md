# [wf-4c237257-04] E1-S4: Pass 3 - Orphan Check

## Parent
Part of [wf-4c237257] Transcript Digestion Feature - **Epic 1: Core Extraction Engine**

## User Story
**As a** user who wants nothing missed
**I want** every orphan statement to be resolved
**So that** 100% of meaningful content is captured

## Description
Implement the third pass that handles all statements marked as orphans in Pass 2. The goal is to achieve 100% coverage.

## Acceptance Criteria

### Scenario 1: Orphan matches existing topic
**Given** an orphan statement that actually relates to an existing topic
**When** Pass 3 re-analyzes with broader context
**Then** the statement is assigned to the correct topic
**And** orphan status is removed

### Scenario 2: Orphan creates new topic
**Given** an orphan statement about something not previously identified
**When** Pass 3 determines it's genuinely new
**Then** a new topic is created in topics.json
**And** the orphan is assigned to this new topic

### Scenario 3: Orphan needs clarification
**Given** an orphan statement that's ambiguous
**When** Pass 3 cannot confidently resolve it
**Then** it remains in orphans.json with `needs_clarification: true`
**And** a clarification question is generated

### Scenario 4: General catch-all
**Given** orphan statements that are valid but miscellaneous
**When** Pass 3 processes them
**Then** they're assigned to a "General" topic

### Scenario 5: Coverage verification
**Given** Pass 3 completes
**When** calculating coverage
**Then** every meaningful statement has a topic_id
**And** coverage = 100% (or gaps clearly identified)

## Technical Notes
- **Re-analysis strategy**: Use full transcript context
- **New topic creation**: Only if genuinely distinct
- **Output**: Updated `statement-map.json` and `orphans.json`

## Dependencies
- [wf-4c237257-03] Statement mapping must be complete

## Scope
**M** - Logic to achieve 100% coverage
