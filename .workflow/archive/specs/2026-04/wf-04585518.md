# [wf-04585518] Surface effort.level and thinking.enabled in status line

## User Story
**As a** WogiFlow user configuring the status line
**I want** `{effort}` and `{thinking}` tokens available in the status-line template
**So that** I can see at a glance which effort level is active and whether thinking is on, without running `/effort` or checking `/config`

## Description
Claude Code 2.1.119 extends the status-line stdin JSON with `effort.level` (`low` / `medium` / `high` / `xhigh` / `max`) and `thinking.enabled` (boolean). `scripts/flow-statusline-setup.js:25-46` defines four preset FORMATS (minimal, compact, standard, detailed) that map tokens to stdin fields — none expose the new fields yet. This task adds token support and updates the setup docs; it does not force any preset to include them.

## Acceptance Criteria

### Scenario 1: Effort token
**Given** the user selects a format containing `{{effort.level}}`
**And** the active Claude Code version emits `effort.level` in stdin JSON
**When** the status line renders
**Then** the token is substituted with the current effort level string
**And** long identifiers (e.g. `xhigh`, `max`) render without truncation

### Scenario 2: Thinking token
**Given** the user selects a format containing `{{thinking.enabled}}` (or a Handlebars conditional using it)
**And** CC emits `thinking.enabled`
**When** the status line renders
**Then** the value reflects the current thinking state (truthy/falsy)

### Scenario 3: Fallback for older Claude Code
**Given** CC < 2.1.119 is running and does not emit `effort` / `thinking`
**When** a format uses those tokens
**Then** they render empty (Handlebars default for missing paths) without throwing
**And** surrounding punctuation in the format string collapses gracefully (use `{{#if effort}}` guards in any preset that references them)

### Scenario 4: Docs updated
**Given** `.claude/commands/wogi-statusline-setup.md` documents available tokens
**When** a user reads the docs
**Then** `effort.level` and `thinking.enabled` are listed alongside `model`, `task`, `context_window.used_percentage`, `skill`, `workspace.git_worktree`
**And** at least one example format demonstrates conditional usage

## Technical Notes
- **Files**:
  - `scripts/flow-statusline-setup.js:25-46` — extend FORMATS documentation and/or add a new preset (e.g. `advanced`) that includes effort/thinking. Do NOT change existing preset strings (users may have them saved).
