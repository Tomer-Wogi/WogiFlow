## Goal

Replace prose-only `.claude/docs/phases/*.md` with parallel structured YAML definitions at `.workflow/modes/*.yaml`. Keep the prose as authoritative phase instructions (those are user-facing), but add a machine-readable sidecar with phase metadata that downstream features (C2, E1) can consume programmatically.

## Integration Point

- `.workflow/modes/*.yaml` — 5 files, one per phase (exploring, spec_review, coding, validating, completing).
- `lib/mode-schema.js` — loader + validator.
- `scripts/hooks/core/phase-read-gate.js` — unchanged enforcement (still tracks prose reads); optionally augmented to also surface YAML metadata to downstream hooks.
- `scripts/flow-prompt-composer.js` — if useful, may inject `roleDefinition` or `customInstructions` into system prompt at phase transition (deferred to a follow-up if not needed now).

## Acceptance Criteria

1. Schema defined (WogiFlow-native, no Kilo reference): `name`, `roleDefinition` (short), `whenToUse`, `customInstructions` (optional), `allowedToolGroups[]` (optional, advisory only — not an enforcement mechanism).
2. 5 YAML files created at `.workflow/modes/{exploring,spec_review,coding,validating,completing}.yaml`. Metadata-only — prose stays in `.claude/docs/phases/*.md`.
3. `lib/mode-schema.js` exports `loadMode(name)` + `validateMode(obj)`. Malformed YAML → throw with specific field error.
4. Downstream-ready: C2 (`wf-4434851f`) and E1 (`wf-8d635d0e`) can `require('lib/mode-schema').loadMode('coding')` to get structured data.
5. No backward-compat shim needed — prose files are untouched; YAML is additive.
6. Tests: schema validation (valid + 3 invalid cases), loader round-trip, all 5 files validate.
