## Goal

On `coding → validating` phase transition, spawn a parallel review in a separate git worktree via WogiFlow's existing workspace manager pattern. Findings write to `.workflow/state/auto-review-findings.json` as structured records that the Completion Truth Gate consults before allowing task close. Non-blocking.

## Integration Point

- Phase transition hook (`coding → validating`) invokes `flow auto-review start --task <id>`.
- `lib/worktree-review.js` — creates worktree, spawns workspace worker session (existing `lib/workspace.js` pattern).
- Findings return via standard workspace message-bus (JSON today; SQLite after G3 wf-3635574e lands).
- `flow-completion-truth-gate.js` reads `.workflow/state/auto-review-findings.json` at its existing gate point.

**Explicitly NOT in scope**: per-task model selection. The review session runs on whatever Claude Code model is globally active. Cost-reduction via cheaper model is blocked by a Claude Code feature (per-task model selection) and is called out as a known limitation, not a deliverable.

## Acceptance Criteria

1. Phase transition `coding → validating` spawns worktree review as background workspace worker (existing `lib/workspace.js` pattern).
2. Worker produces findings as JSON records: `{severity: 'low'|'medium'|'high', file, line, claim, evidence}`.
3. Findings land at `.workflow/state/auto-review-findings.json` (array; last-write-wins per task).
4. Completion Truth Gate reads the file — high-severity findings downgrade completion claims (existing downgrade mechanism, no new gate logic).
5. Non-blocking: validation proceeds if review takes longer than `config.autoReview.timeoutMs` (default 90000). Timeout marks gate as `unverified-review-timeout`, doesn't fail.
6. Known limitation documented: review runs on the session's global model; per-task cost reduction is a future Claude Code feature.
7. Tests: findings incorporation, timeout behaviour, high-severity downgrade path, gate passthrough on no findings.
