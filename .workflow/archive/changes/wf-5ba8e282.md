# wf-5ba8e282: Adapt WogiFlow for Claude Code 2.1.50

## User Story

As a WogiFlow user upgrading to Claude Code 2.1.50, I want WogiFlow to detect incompatible modes and leverage new platform features, so that my workflow remains enforced and takes advantage of improved capabilities.

## Description

Claude Code 2.1.50 introduces several changes that affect WogiFlow:
- `CLAUDE_CODE_SIMPLE` now disables hooks, MCP, and CLAUDE.md — silently breaking all WogiFlow enforcement
- `CLAUDE_CODE_DISABLE_1M_CONTEXT` reduces the context window, affecting our context estimator thresholds
- New `WorktreeCreate`/`WorktreeRemove` hook events enable better worktree lifecycle management
- `isolation: "worktree"` in agent definitions simplifies parallel execution
- `claude agents` CLI command can enhance health diagnostics

This story addresses all 5 items from the 2.1.50 impact assessment.

## Acceptance Criteria

### Scenario 1: CLAUDE_CODE_SIMPLE detection at session start
Given a user starts a session with CLAUDE_CODE_SIMPLE=true
When the SessionStart hook runs
Then a warning is injected into the session context explaining that WogiFlow hooks, rules, and CLAUDE.md are disabled
And the warning includes guidance to unset CLAUDE_CODE_SIMPLE for full workflow enforcement

### Scenario 2: CLAUDE_CODE_DISABLE_1M_CONTEXT adjusts context estimator
Given a user has CLAUDE_CODE_DISABLE_1M_CONTEXT set
When the context estimator calculates safe thresholds (Step 0.25)
Then the safe threshold is reduced from 0.95 to 0.85 (accounting for smaller context window)
And the emergency threshold is reduced from 0.90 to 0.80
And a log message notes the adjustment reason

### Scenario 3: Health check reports Claude Code 2.1.50 features
Given the user runs /wogi-health
When checkClaudeCodeVersion() executes
Then it reports whether version >= 2.1.50
And it lists available 2.1.50 features (worktree hooks, agent isolation, agent listing)
And it runs `claude agents` to verify agent configuration if version >= 2.1.50

### Scenario 4: WorktreeCreate/Remove hooks registered in settings
Given WogiFlow is installed or synced
When .claude/settings.local.json is generated
Then WorktreeCreate and WorktreeRemove hook entries are present
And WorktreeCreate copies essential .workflow/state files to the new worktree
And WorktreeRemove cleans up session state from the removed worktree

### Scenario 5: Parallel execution documents worktree isolation option
Given tasks are available for parallel execution
When flow-parallel.js describes available isolation modes
Then it mentions `isolation: "worktree"` as a declarative option for agent-based parallel execution
And it documents this in a code comment for future adoption (no behavioral change yet — research only)
