## User Story

As a developer using WogiFlow with Teams, I want my local state to automatically sync with the team server when I start and end sessions, so that I always have the latest team rules and my work is shared back.

## Description

This story creates the client-side sync module in the @wogiflow/teams package. It hooks into WogiFlow's session-start (pull) and session-end (push) lifecycle, handles offline queuing, and integrates with the existing extension registry.

## Acceptance Criteria

### AC1: Session-start pulls team state
Given a team-enabled project
When a Claude Code session starts
Then the client pulls all changed files since last sync
And merges them into local `.workflow/state/` files
And the pull is non-blocking (session starts immediately)

### AC2: Session-end pushes local changes
Given local state files that changed during the session
When the session ends
Then changed files are pushed to the server
And the push includes version vectors for conflict detection

### AC3: Offline queue for failed syncs
Given the server is unreachable
When a session-end push fails
Then changes are queued to `~/.wogiflow/sync-queue.json`
And the next session-start replays the queue before pulling

### AC4: Smart diff detection
Given local state files
When determining what to push
Then only files whose SHA256 hash differs from last sync are pushed
And unchanged files are skipped (bandwidth optimization)

### AC5: Post-sync regeneration
Given a successful pull that updated decisions.md
When the merge completes
Then `section-index.json` is regenerated
And `.claude/rules/` are regenerated via flow-rules-sync.js
And `component-index.json` is regenerated if app-map changed

### AC6: Auth token management
Given the client needs to call sync APIs
When making requests
Then it uses the stored JWT from `~/.wogiflow/auth.json`
And automatically refreshes if expired (using refresh token)
And if refresh fails, prompts user to re-authenticate

### AC7: Config-driven sync
Given the team config section in `.workflow/config.json`
When `team.enabled` is false or missing
Then no sync operations occur
And the hooks are no-ops

### AC8: Heartbeat during long sessions
Given a claimed task during an active session
When 10 minutes pass
Then the client sends a heartbeat to extend the lock TTL
And if heartbeat fails, warns the user (lock may expire)

### AC9: Sync status reporting
Given a completed sync operation
When the session starts
Then a brief status line is shown:
  "Team sync: 3 files pulled (decisions.md, ready.json, app-map.md)"
And errors are shown as warnings, not blockers

### AC10: Extension registry integration
Given the @wogiflow/teams package
When installed in a project
Then it registers via the extension registry
And hooks are auto-loaded without modifying WogiFlow core

## Technical Notes

### Files to Create (in wogiflow-cloud)

- `packages/client/lib/sync-client.js` — HTTP client for sync API
- `packages/client/lib/sync-engine.js` — Local merge + hash comparison
- `packages/client/lib/auth-client.js` — JWT storage + refresh
- `packages/client/lib/offline-queue.js` — Queue management
- `packages/client/hooks/session-start-cloud.js` — Pull hook
- `packages/client/hooks/session-end-cloud.js` — Push hook
- `packages/client/hooks/task-heartbeat.js` — Periodic heartbeat
- `packages/client/tests/unit/sync-client.test.js` — Tests

### Minor Changes to Free Package (wogi-flow)

- None required — uses existing extension registry and hook architecture

### Auth Token Storage

```
~/.wogiflow/
  auth.json          # {accessToken, refreshToken, expiresAt, userId, teamId}
  sync-queue.json    # [{fileKey, content, version, timestamp}, ...]
  sync-state.json    # {lastSyncAt, fileHashes: {decisions: "sha256...", ...}}
```
