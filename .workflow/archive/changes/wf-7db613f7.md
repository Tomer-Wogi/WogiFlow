# Config Consolidation - Remove Static Data from Config

**ID**: wf-7db613f7
**Epic**: wf-ea2c59c1 (WogiFlow Deep Optimization)
**Type**: refactor | **Level**: L1 | **Priority**: P1

## Problem

~180 lines of config.json contain static data that never changes per-project (framework patterns, URLs, phase definitions, priority labels, keywords, model lists). These waste tokens every session.

## Acceptance Criteria

1. **Given** skillLearning.frameworkDetectionPatterns (40 lines), **When** removed from config, **Then** defaults are defined in flow-skill-learning.js and merged with any config overrides
2. **Given** skillLearning.officialDocsUrls (8 lines), **When** removed from config, **Then** defaults in code
3. **Given** phases.definitions (60 lines), **When** removed from config, **Then** defaults in flow-phase.js
4. **Given** priorities.levels (20 lines), **When** removed from config, **Then** defaults in flow-utils.js or flow-ready.js
5. **Given** storyDecomposition.classification.keywords (25 lines), **When** removed from config, **Then** defaults in flow-story.js
6. **Given** hybrid.cloudProviders (25 lines), **When** removed from config, **Then** defaults in flow-hybrid.js
7. **Given** disabled features have full sub-config, **When** feature is disabled, **Then** config stores only `enabled: false` and code provides defaults when enabled

## Strategy

Create a `getConfigWithDefaults(key)` pattern:
```javascript
function getConfigWithDefaults(key) {
  const userConfig = getConfig()[key] || {};
  const defaults = CONFIG_DEFAULTS[key] || {};
  return deepMerge(defaults, userConfig);
}
```

## Files to Change

- `.workflow/config.json` — remove static data
- `scripts/flow-utils.js` — add CONFIG_DEFAULTS and getConfigWithDefaults()
- Individual scripts that define their defaults locally

## Boundary Declarations

- Do NOT change default values — exact same behavior when features are enabled
- Config overrides must still work (user can override any default)
