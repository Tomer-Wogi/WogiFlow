# [wf-1488a40e] Expand wogi-start triage to route to all WogiFlow commands

## User Story
**As a** WogiFlow user
**I want** `/wogi-start` to recognize and route to all WogiFlow commands (review, research, debug, status, morning, etc.)
**So that** every user request is intelligently routed to the right workflow regardless of how they phrase it

## Description
Currently `/wogi-start` triage has 5 categories: Exploration, Operational, Quick Fix, Bug, Implementation. Many WogiFlow commands are unreachable through triage — "code review", "research this", "morning briefing", "show status", etc. fall to "unknown" and ask for clarification. This adds new pattern categories for review, research, debug, and workflow commands, and updates the classification priority order.

## Acceptance Criteria

### Scenario 1: Review requests route to /wogi-review
**Given** a user request like "code review" or "review what we did"
**When** `classifyRequest()` runs
**Then** it returns `{ category: 'review', action: 'route-command', command: '/wogi-review' }`

### Scenario 2: Peer review requests route to /wogi-peer-review
**Given** a user request like "peer review" or "multi-model review"
**When** `classifyRequest()` runs
**Then** it returns `{ category: 'review', action: 'route-command', command: '/wogi-peer-review' }`

### Scenario 3: Research requests route to /wogi-research
**Given** a user request like "does X support Y?" or "is it possible to..."
**When** `classifyRequest()` runs
**Then** it returns `{ category: 'research', action: 'route-command', command: '/wogi-research' }`

### Scenario 4: Debug requests route to /wogi-debug-hypothesis
**Given** a user request like "debug this" or "investigate the root cause"
**When** `classifyRequest()` runs
**Then** it returns `{ category: 'debug', action: 'route-command', command: '/wogi-debug-hypothesis' }`

### Scenario 5: Workflow commands route to correct /wogi-* command
**Given** a user request like "morning briefing", "show tasks", "project status", "wrap up", "compact context", "show roadmap", "standup"
**When** `classifyRequest()` runs
**Then** it returns the correct `command` for each (e.g., '/wogi-morning', '/wogi-ready', '/wogi-status', etc.)

### Scenario 6: wogi-start.md triage table updated
**Given** the skill prompt in `.claude/commands/wogi-start.md`
**When** the triage section is read
**Then** it includes all new categories with patterns, actions, and examples

### Scenario 7: Existing categories still work
**Given** existing request types (exploration, operational, bug, quick-fix, implementation)
**When** `classifyRequest()` runs
**Then** they still route correctly (no regressions)

### Scenario 8: Natural language detection table is complete
**Given** the CLAUDE.md natural language detection table
**When** compared against all available /wogi-* commands
**Then** all routable commands have trigger phrases in the table

## Technical Notes
- **Files to change**:
  - `scripts/hooks/core/implementation-gate.js` - Add pattern arrays + update classifyRequest()
  - `.claude/commands/wogi-start.md` - Update triage table and examples
  - `CLAUDE.md` - Update natural language detection table
- **Priority order**: workflow > peer-review > review > research > debug > exploration > operational > bug > quick-fix > implementation
- **New action type**: `route-command` with a `command` field specifying which /wogi-* to invoke
