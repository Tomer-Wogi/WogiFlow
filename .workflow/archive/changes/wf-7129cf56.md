# wf-7129cf56 — Enforce Task ID Naming Convention + Workflow Bypass Prevention

## User Story
**As a** WogiFlow user
**I want** task IDs to always follow the `wf-[8hexchars]` hash convention and the agent to always route through `/wogi-*` commands
**So that** validators work correctly, the system is consistent, and no work happens outside the tracked workflow

## Description
The AI agent drifted from two critical conventions: (1) It started creating descriptive task IDs like `wf-skill-overhaul` instead of using `generateTaskId()` which produces `wf-a1b2c3d4` format. This causes `validateTaskId()` in flow-utils.js to fail on these IDs, and breaks sub-task numbering. (2) It launched a Task agent for research directly instead of routing through `/wogi-start` or `/wogi-research`, bypassing the mandatory workflow routing. Both are convention enforcement failures that need code-level prevention, not just documentation.

## Acceptance Criteria

### Scenario 1: Rename active descriptive IDs to hash format
**Given** 4 tasks in ready.json with descriptive IDs: `wf-skill-overhaul`, `wf-manifest-wiring`, `wf-schema-registry`, `wf-service-registry`
**When** I run the fix
**Then** each is renamed to a proper hash ID generated by `generateTaskId()`
**And** their `specPath` fields are updated to point to renamed spec files
**And** the spec `.md` files are renamed to match the new IDs
**And** any `dependsOn` references in ready.json are updated to the new IDs
**And** a mapping comment is added to the spec files: `<!-- Formerly: wf-skill-overhaul -->`

### Scenario 2: Add decision rule for task ID convention
**Given** decisions.md
**When** I add a rule
**Then** a new entry exists under a "Task ID Convention" section stating: "All task IDs MUST be generated by `generateTaskId()` from flow-utils.js. Never manually type a task ID. Format: `wf-[8 lowercase hex chars]`. Descriptive names go in the `title` field, not the `id` field."
**And** the rule references this fix as origin

### Scenario 3: Add feedback patterns for both violations
**Given** feedback-patterns.md
**When** I add entries
**Then** a pattern `descriptive-task-ids` exists documenting the convention drift (count: 20+)
**And** a pattern `workflow-bypass-research` exists documenting the direct Task agent launch without routing through `/wogi-*`
**And** both are marked `Status: Rule Created` pointing to the decisions.md entries

### Scenario 4: Add decision rule for mandatory workflow routing
**Given** decisions.md
**When** I add a rule
**Then** a new entry reinforces: "The AI agent MUST NEVER launch Task agents, read files, or perform any action in response to a user request without first routing through a `/wogi-*` command. Even research questions go through `/wogi-research`. Even simple explorations go through `/wogi-start`. There are zero exemptions."
