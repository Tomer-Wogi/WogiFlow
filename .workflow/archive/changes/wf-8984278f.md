# [wf-8984278f] Implement 3 quality improvements from superpowers analysis


## User Story
**As a** WogiFlow user
**I want** enhanced quality gates inspired by the superpowers plugin
**So that** code review catches issues earlier and repeated failures trigger architectural reassessment

## Description
Based on analysis of the superpowers plugin, implement three improvements:
1. Sequential spec-then-quality review gating (spec must pass before code quality review)
2. 3-strike architectural reassessment with autonomous research (agent analyzes alternatives after 3 failures)
3. Optional pre-task test baseline check (verify tests pass before starting work)

## Acceptance Criteria

### Scenario 1: Sequential spec-then-quality review
**Given** a code review is triggered via `/wogi-review`
**When** the review process starts
**Then** spec verification runs FIRST before any other passes
**And** if spec verification fails, code quality passes are SKIPPED
**And** the user sees "Spec verification must pass before code quality review"

### Scenario 2: 3-strike architectural reassessment - continue
**Given** a task has failed 3 times with the same error type
**When** the 3rd failure occurs
**Then** the agent pauses and analyzes if this is an architectural problem
**And** if agent determines current approach is still best, it logs reasoning and continues
**And** the user sees the agent's analysis

### Scenario 3: 3-strike architectural reassessment - propose alternative
**Given** a task has failed 3 times with the same error type
**When** the agent determines a better architectural approach exists
**Then** the agent researches and documents the alternative approach
**And** the agent presents the alternative to the user for approval
**And** if user approves, the approach switches; if rejected, original continues

### Scenario 4: Pre-task test baseline - enabled
**Given** `config.qualityGates.preTaskBaseline.enabled` is true
**And** the task type is "feature" or "refactor"
**When** `/wogi-start` is invoked
**Then** the project test suite runs before loading task context
**And** if more than `failureThreshold` tests fail, the task is blocked
**And** the user sees which tests are failing

### Scenario 5: Pre-task test baseline - bypass
**Given** pre-task baseline is enabled
**When** `/wogi-start wf-XXX --skip-baseline` is used
**Then** the baseline check is skipped
**And** implementation proceeds normally

### Scenario 6: Pre-task test baseline - disabled by default
**Given** a fresh WogiFlow installation
**When** checking default config
**Then** `preTaskBaseline.enabled` is `false`
**And** no baseline check runs by default

## Technical Notes
- **Files to modify**:
  - `scripts/flow-review.js` - Add spec-first gating logic
  - `scripts/flow-error-recovery.js` - Add 3-strike reassessment
  - `scripts/flow-start.js` - Add pre-task baseline check
  - `.workflow/config.json` - Add new config options
- **New functions**:
  - `runSpecFirstReview()` in flow-review.js
  - `checkArchitecturalReassessment()` in flow-error-recovery.js
  - `runPreTaskBaseline()` in flow-start.js
- **Config additions**:
  ```json
  "qualityGates": {
    "preTaskBaseline": {
      "enabled": false,
      "failureThreshold": 5,
      "skipForTypes": ["bugfix", "quick-fix"]
    }
  },
  "errorRecovery": {
    "architecturalReassessment": {
      "enabled": true,
      "strikeCount": 3,
      "autoResearch": true
    }
  },
  "review": {
    "specFirstGating": true
  }
  ```
