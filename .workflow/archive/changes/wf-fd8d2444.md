# [wf-fd8d2444] WogiFlow Memory Enhancement - Automatic Observation Capture


## User Story
**As a** developer using WogiFlow
**I want** automatic capture of all tool uses with progressive disclosure search
**So that** I can query my session history efficiently without manually remembering facts

## Description
Add automatic observation capture inspired by claude-mem to WogiFlow's memory system. Every tool use is automatically captured with smart summarization, enabling progressive disclosure search (IDs → summaries → full details) for ~10x token savings. Includes timeline context queries and hybrid FTS5 + semantic search.

## Acceptance Criteria

### Scenario 1: Automatic observation capture
**Given** observation capture is enabled in config
**When** any tool is executed (Edit, Write, Bash, Read, Grep, etc.)
**Then** the observation is automatically stored with:
  - Tool name, input summary, output summary
  - Full input/output (truncated to maxInputSize/maxOutputSize)
  - Session ID, timestamp, duration, success status
  - Context task ID if a task is active
**And** the capture is non-blocking (never fails the tool execution)

### Scenario 2: Progressive disclosure search (search_index MCP tool)
**Given** observations exist in the database
**When** I call `search_index` with a query
**Then** I receive only IDs and compact summaries (~50-100 tokens)
**And** this is much cheaper than fetching full details

### Scenario 3: Fetch full observation details (get_observations MCP tool)
**Given** I have observation IDs from search_index
**When** I call `get_observations` with those IDs
**Then** I receive full observation details including full_input and full_output
**And** I can optionally include or exclude full content

### Scenario 4: Timeline context queries (get_timeline MCP tool)
**Given** I have an observation ID or timestamp as anchor
**When** I call `get_timeline` with before=3 and after=3
**Then** I receive observations surrounding that anchor point
**And** I can filter by tool_name

### Scenario 5: Tool skip configuration
**Given** skipTools is configured with ["Read", "Glob"]
**When** a Read or Glob tool is executed
**Then** no observation is captured for that tool
**And** other tools are still captured normally

### Scenario 6: Existing functionality preserved
**Given** the existing MCP tools (recall_facts, remember_fact, forget_fact)
**When** I use them as before
**Then** they work exactly as before without any changes
**And** CLI commands (flow entropy, flow memory-sync) work unchanged
