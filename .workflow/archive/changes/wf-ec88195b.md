# Phase C2 Client-Side — Community Knowledge Local Surfacing

**ID:** wf-ec88195b
**Type:** story
**Feature:** community
**Priority:** P1
**Created:** 2026-02-25

## User Story

As a WogiFlow user with community sharing enabled, I want pulled community knowledge to be merged into my local model adapters and error recovery files, so that community learnings enrich my local workflow automatically.

## Description

Phase C1 established push/pull and display of community knowledge. Phase C2 client-side merges pulled knowledge into local state files so it persists beyond the session context injection. This makes community intelligence available to all workflow components (not just the session-start display).

## Acceptance Criteria

### AC1: Merge model intelligence into local model adapters
**Given** community knowledge contains model intelligence entries
**When** the session-start hook pulls fresh community data
**Then** each model's learnings are appended to the corresponding `.workflow/model-adapters/[model].md` file under a `## Community Learnings` section, without duplicating existing entries

### AC2: Merge error strategies into local adaptive-learning.json
**Given** community knowledge contains error recovery strategies
**When** the session-start hook pulls fresh community data
**Then** new strategies are added to `.workflow/state/adaptive-learning.json` under a `communityStrategies` key, deduped by category+strategy pair

### AC3: Merge patterns into local feedback-patterns as informational
**Given** community knowledge contains converged patterns
**When** the session-start hook pulls fresh community data
**Then** patterns are appended to `.workflow/state/feedback-patterns.md` with a `community-` prefix and `Informational` status (not enforced)

### AC4: Idempotent merging — no duplicates on repeated pulls
**Given** community knowledge was already merged in a previous session
**When** session-start pulls the same data again (from cache or server)
**Then** no duplicate entries are created in any local file

### AC5: Session-start hook calls merge after pull
**Given** community sharing is enabled in config
**When** session-start hook runs and pulls community knowledge
**Then** `mergeCommunityKnowledge()` is called with the pulled data and local files are updated

## Boundaries

- Do NOT modify server-side code (wogiflow-cloud repo)
- Do NOT change the existing session-context.js formatting (it already works)
- Do NOT enforce community patterns as rules — they are informational only
- Do NOT create model adapter files that don't already exist (only append to existing)

## Technical Notes

### Files to Modify
- `scripts/flow-community.js` — Add `mergeCommunityKnowledge()` and helper functions
- `scripts/hooks/entry/claude-code/session-start.js` — Call merge after pull

### Implementation Approach
- Add `mergeCommunityKnowledge(knowledge, config)` to flow-community.js
- Add `mergeModelIntelligence(items)` — appends to model adapter .md files
- Add `mergeErrorStrategies(items)` — adds to adaptive-learning.json
- Add `mergePatterns(items)` — appends to feedback-patterns.md
- All merge functions are idempotent — check for existing entries before appending
- Use marker comments (`<!-- community-knowledge -->`) in .md files for dedup

## Test Strategy

- Syntax check all modified JS files
- Verify merge functions handle missing directories/files gracefully
- Verify idempotent behavior (double-merge produces same output)
