# [wf-085f189d] Fix research protocol - add mandatory verification step before recommendations

## User Story
**As a** WogiFlow user
**I want** the AI to verify each recommendation against the existing codebase before suggesting it
**So that** I don't waste time implementing features that already exist or create regressions

## Description
When the AI performs external research (e.g., "What can we learn from Crush?"), it currently makes recommendations without verifying if WogiFlow already has equivalent functionality. This led to suggesting "provider compatibility layer" when `flow-providers.js` already implements this comprehensively. The research protocol needs a mandatory verification step that forces the AI to search the local codebase for each recommendation before presenting it.

## Acceptance Criteria

### Scenario 1: External comparison research with verification
**Given** a user asks "What can we learn from [external tool] for [feature]?"
**When** the AI completes external research and identifies potential improvements
**Then** for EACH recommendation, the AI MUST:
  1. Search WogiFlow codebase for equivalent functionality
  2. Read at least one potentially relevant file
  3. Mark recommendation as EXISTS/PARTIAL/MISSING
**And** only recommendations marked MISSING are presented to user

### Scenario 2: Recommendation includes verification evidence
**Given** the AI is about to recommend "Add feature X"
**When** the recommendation is presented
**Then** it MUST include:
  - Search patterns used (e.g., "Searched: provider, adapter, model")
  - Files checked (e.g., "Read: flow-providers.js, flow-model-adapter.js")
  - Status (EXISTS/PARTIAL/MISSING)
**And** recommendations with EXISTS status are NOT presented as "we should add"

### Scenario 3: Protocol injection includes verification reminder
**Given** the research protocol is auto-triggered
**When** the protocol steps are injected into AI context
**Then** Phase 5 (Synthesis) MUST include explicit reminder:
  "Before recommending 'Add X', verify X doesn't already exist in codebase"

### Scenario 4: Correction recorded for protocol violations
**Given** this is a significant workflow bug
**When** the fix is complete
**Then** a correction report (CORR-001) is created documenting:
  - What happened (ignored protocol)
  - Root cause (no verification checkpoint)
  - Fix applied (added verification step)
  - Prevention measures
