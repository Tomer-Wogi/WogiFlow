# [wf-2639ad7d] Fix wogi-review to execute all 5 designed phases

## User Story
**As a** WogiFlow user running code reviews
**I want** `/wogi-review` to execute ALL 5 designed phases (not just ~40%)
**So that** code reviews are comprehensive, standards-compliant, and produce actionable fix tasks

## Description
The wogi-review skill document describes a 5-phase review process, but in practice only Phases 1-2 (partially) execute. Phase 2 only launches 3 core agents — project-rules agents (auto-generated from decisions.md) and the optional performance agent are never spawned. Phase 2.5 (git-verified claim checking) is completely missing. Phase 5 (post-review workflow with fix loop, learning capture, and task creation) is never executed. The fix is primarily about ensuring the AI follows through all phases and spawning the right agents.

Key insight: wogi-review is an AI-instruction-driven skill. The "implementation" is about making the instructions clearer, adding enforcement checkpoints, and ensuring Claude follows through all 5 phases sequentially.

## Acceptance Criteria

### Scenario 1: Phase 2 launches project-rules agents from decisions.md
**Given** `config.review.agents.projectRules` is true
**When** `/wogi-review` reaches Phase 2 (AI Review)
**Then** decisions.md is parsed for substantive rule sections
**And** a focused review agent is spawned for each qualifying category (alongside the 3 core agents)
**And** total agents are capped at `config.review.agents.maxParallelAgents` (default: 6)
**And** project-rules findings use the format: `{ category: "[CATEGORY_NAME]", agent: "project-rules-[slug]" }`

### Scenario 2: Phase 2 launches optional performance agent
**Given** `config.review.agents.optional` includes "performance"
**When** `/wogi-review` reaches Phase 2
**Then** a performance review agent is spawned using `.workflow/agents/performance.md` checklist
**And** performance findings are included in the consolidated results

### Scenario 3: Adversarial minimum findings enforced
**Given** `config.review.minFindings` is 3
**When** any review agent returns fewer than 3 findings
**Then** the agent's output includes a `clean-justification` finding explaining why code is clean
**And** the consolidation report flags this prominently

### Scenario 4: Phase 2.5 git-verified claim checking executes
**Given** the reviewed task has a spec file (`.workflow/changes/wf-XXXXXXXX.md`)
**When** Phase 2 (AI review) completes
**Then** Phase 2.5 runs: spec deliverables are cross-referenced against `git diff`
**And** files promised in spec but NOT in git diff are flagged as BLOCKER
**And** files in git diff but NOT in spec are flagged as WARNING (scope creep)
**And** results are displayed in the review output

### Scenario 5: Phase 3 standards compliance runs after AI review
**Given** `--skip-standards` flag is NOT set
**When** Phase 2.5 completes
**Then** Phase 3 runs standards compliance checks using `flow-standards-checker.js`
**And** MUST_FIX violations block review completion
**And** results are displayed in the standardized format

### Scenario 6: Phase 4 solution optimization runs
**Given** `--skip-optimization` flag is NOT set
**When** Phase 3 completes
**Then** Phase 4 runs solution optimization using `flow-solution-optimizer.js`
**And** suggestions are displayed as non-blocking recommendations

### Scenario 7: Phase 5 post-review workflow executes
**Given** all review phases have completed
**When** Phase 5 starts
**Then** findings are persisted to `.workflow/state/last-review.json`
**And** user is offered options: [1] Fix all, [2] Fix critical first, [3] Review tasks manually
**And** if user chooses fix: findings are converted to TodoWrite items and a fix loop begins
**And** after fixes: re-verification runs (lint, typecheck, tests)
**And** learning loop captures correction patterns to `feedback-patterns.md`

### Scenario 8: All phases execute in sequence with clear output
**Given** a standard `/wogi-review` invocation
**When** the full review completes
**Then** each phase displays a clear section header in the output
**And** phase results are displayed progressively (not all at end)
**And** the summary shows: "Phases: 5/5 executed" (or N/5 if some were skipped by flags)

## Technical Notes

### Key Architecture Insight
The review system has TWO layers:
1. **Runtime scripts** (flow-review.js, flow-standards-checker.js, etc.) — handle file loading, verification, standards
2. **AI instructions** (wogi-review.md skill) — describe agent spawning, post-review workflow

The fix is primarily about making the AI instructions enforceable and complete:
- Add explicit phase checkpoints
- Add project-rules agent spawning instructions
- Add git-verified claim checking instructions
- Ensure all runtime scripts are invoked at the right phase

### Files to Modify
- `.claude/commands/wogi-review.md` — Restructure for phase enforcement, add explicit agent spawn instructions
- `scripts/flow-review.js` — May need updates for findings persistence format

### Existing Runtime Support (Already Implemented)
- Phase 1: `flow-spec-verifier.js`, lint/typecheck/test in `flow-review.js`
- Phase 3: `flow-standards-checker.js`, `flow-standards-gate.js`
- Phase 4: `flow-solution-optimizer.js`
- Multi-pass: `flow-review-passes/` (structure, logic, security, integration)

### Config Keys (Already Exist)
- `review.agents.core`, `review.agents.optional`, `review.agents.projectRules`
- `review.minFindings`, `review.requireJustificationIfClean`
- `review.gitVerifiedClaims.enabled`
- `standardsCompliance.enabled`, `standardsCompliance.mode`
- `review.agents.maxParallelAgents`

### No New UI Components
This is a CLI/workflow-only change. No wiring section needed.
