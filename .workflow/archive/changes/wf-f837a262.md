# [wf-f837a262] Add centralized script resolver to replace hardcoded npm/npx commands


## User Story
**As a** WogiFlow user with a project that uses non-standard script names or non-npm package managers
**I want** WogiFlow to auto-detect my package manager and script names instead of hardcoding `npm run typecheck`
**So that** quality gates, spec generation, and verification actually work for my project

## Description
WogiFlow hardcodes `npm run typecheck`, `npm run lint`, `npm test`, and `npm run build` in 8+ scripts. When a project uses different script names (e.g., `type-check` instead of `typecheck`) or different package managers (yarn, pnpm, bun), these commands silently fail — quality gates report false failures or skip verification entirely.

`flow-workflow.js` already has solid package manager detection (`detectProjectType()`) and command mapping (`getQualityCommand()`). This task extracts that logic into a shared resolver and replaces all hardcoded invocations across the codebase. It also adds a session-start validation to warn when script names don't align.

## Acceptance Criteria

### Scenario 1: Shared resolver utility resolves commands correctly
**Given** a project with `pnpm-lock.yaml` and a `package.json` containing `"type-check": "tsc --noEmit"`
**When** `getCommand('typecheck')` is called
**Then** it returns `pnpm type-check` (detected package manager + resolved alias)

### Scenario 2: Config override takes priority over auto-detection
**Given** `.workflow/config.json` contains `"scripts": { "typecheck": "npm run custom-tc" }`
**When** `getCommand('typecheck')` is called
**Then** it returns `npm run custom-tc` (config override wins)

### Scenario 3: Auto-detection with alias matching
**Given** a `package.json` with scripts: `{ "type-check": "...", "lint:fix": "..." }`
**When** `getCommand('typecheck')` is called
**Then** it matches `type-check` as an alias for `typecheck` and returns the correct command
**And** `getCommand('fix')` matches `lint:fix` as an alias for `fix`

### Scenario 4: Graceful fallback when script not found
**Given** a `package.json` that has no `typecheck`, `type-check`, or `tsc` script
**When** `getCommand('typecheck')` is called
**Then** it returns `null` (not a broken command that will fail silently)
**And** callers can check for null and skip the step with a warning

### Scenario 5: All hardcoded scripts replaced in flow-*.js files
**Given** the updated codebase
**When** grepping for `'npm run typecheck'`, `'npm run lint'`, `'npm test'`, `'npm run build'` in scripts/flow-*.js
**Then** zero matches are found (all replaced with resolver calls)
**And** config.json validation/afterTaskComplete/beforeCommit sections use resolver references

### Scenario 6: Session start drift detection
**Given** a project where `package.json` scripts changed since last session
**When** a new Claude Code session starts
**Then** the SessionStart hook outputs a warning if expected scripts are missing
**And** suggests the closest alias match (e.g., "No 'typecheck' script found. Did you mean 'type-check'?")

### Scenario 7: Package manager detection from lockfiles
**Given** a project with `yarn.lock`
**When** the resolver generates a command for `lint`
**Then** it uses `yarn lint` (not `npm run lint`)
**And** for exec-style commands uses `yarn dlx` (not `npx`)

## Technical Notes
- **Reuse existing**:
  - `flow-workflow.js` → `detectProjectType()` function (language + package manager detection)
  - `flow-workflow.js` → `getQualityCommand()` function (command mapping table)
  - `flow-strict-adherence.js` → `PACKAGE_COMMANDS` mapping (install/add/remove/run/exec per manager)
- **Create new**:
  - `scripts/flow-script-resolver.js` — shared resolver utility
    - Exports: `getCommand(name)`, `detectPackageManager()`, `resolveScriptName(name)`, `validateScripts()`
    - Alias map: `{ typecheck: ['type-check', 'tsc', 'check-types'], fix: ['lint:fix', 'eslint:fix'], coverage: ['test:coverage', 'test:cov'] }`
- **Files to update** (replace hardcoded commands):
  - `scripts/flow-task-enforcer.js` — `npm test` → `getCommand('test')`
  - `scripts/flow-orchestrate.js` — `npx tsc --noEmit`, `npx eslint` → resolver
  - `scripts/flow-spec-generator.js` — all 4 hardcoded commands
  - `scripts/flow-verify.js` — 7+ npx invocations
  - `scripts/flow-step-coverage.js` — coverage command detection
  - `scripts/flow-regression.js` — test runner detection
  - `.workflow/config.json` — validation.afterTaskComplete, validation.beforeCommit sections
- **Config addition** (`.workflow/config.json`):
  ```json
  "scripts": {
    "lint": null,
    "typecheck": null,
    "test": null,
    "build": null,
    "coverage": null,
    "fix": null
  }
  ```
  `null` = auto-detect. String value = user override.
- **SessionStart hook addition**: Add script validation call to `scripts/hooks/entry/claude-code/session-start.js`

## Test Strategy
- [ ] Unit: `node --check scripts/flow-script-resolver.js` (syntax validation)
- [ ] Integration: Run resolver against WogiFlow's own package.json and verify correct results
- [ ] Verification: `grep -r "npm run typecheck\|npm run lint\|npm test\|npm run build" scripts/flow-*.js` returns zero matches

## Dependencies
- None (builds on existing `flow-workflow.js` detection)

## Complexity
Medium — 1 new utility file, 6-7 files to update, config schema addition, hook addition

## Out of Scope
- Rewriting `flow-strict-adherence.js` or `flow-workflow.js` (they already work well — we extract from them, not replace)
- Supporting non-Node.js projects in the resolver (flow-workflow.js already handles Go/Rust/Python — we focus on the Node.js path which is where hardcoding hurts)
- Auto-fixing mismatched scripts (we warn, not auto-correct)

## Boundaries (DO NOT MODIFY)
- `scripts/flow-workflow.js` — keep `detectProjectType()` and `getQualityCommand()` intact; resolver imports from here
- `scripts/flow-strict-adherence.js` — keep `PACKAGE_COMMANDS` intact; resolver may import from here
- `.claude/settings.local.json` — no changes needed (gitignored)
