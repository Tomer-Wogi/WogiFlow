# [wf-6f5c00c4] Add standards compliance to wogi-start quality gates

## User Story
**As a** developer using WogiFlow
**I want** standards compliance checks integrated into task completion
**So that** violations are caught early (shift left) and fixed before review, preventing rework

## Description
Integrate the full standards compliance checker (`flow-standards-checker.js`) into wogi-start's quality gates with smart scoping based on task type. Standards violations will block task completion, and the existing retry loop will handle fixing them. This also includes a learning system that tracks violations and promotes repeated patterns to rules.

## Acceptance Criteria

### Scenario 1: Standards check runs at task completion
**Given** a task is being completed via wogi-start
**When** all acceptance criteria are implemented and wiring is verified
**Then** the standards compliance check runs automatically (Step 3.7)
**And** the check is scoped based on task type (component, utility, bugfix, etc.)

### Scenario 2: Smart scoping by task type
**Given** a task has a type (component, utility, api, feature, bugfix, refactor)
**When** the standards check runs
**Then** only relevant checks execute:
  - component task: naming, components, security
  - utility task: naming, functions, security
  - bugfix task: naming, security (minimal)
  - feature task: all checks

### Scenario 3: Violations block with retry feedback
**Given** the standards check finds must-fix violations
**When** the check completes
**Then** the task is blocked from completion
**And** clear feedback is provided with specific fixes needed
**And** the agent can retry after fixing violations

### Scenario 4: Learning from violations
**Given** a standards violation is detected
**When** the violation is of a trackable type (naming, duplication, security)
**Then** the violation is recorded to feedback-patterns.md
**And** if the same pattern occurs 3+ times, a rule is promoted to decisions.md
**And** prevention prompts are generated for future tasks

### Scenario 5: Review skips redundant check
**Given** a task completed with standards check passing
**When** wogi-review runs on the same changes
**Then** the standards check notes "already passed at task completion"
**And** optionally skips the redundant check

### Scenario 6: Configuration controls behavior
**Given** config.json has standardsCompliance settings
**When** enabled is false
**Then** the standards check is skipped
**And** when mode is "warn" instead of "block", violations don't block completion
