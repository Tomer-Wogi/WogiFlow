# [wf-2d3b69b3] Fix Stop hook JSON schema validation error

## User Story
**As a** WogiFlow user
**I want** the Stop hook to output valid JSON per Claude Code's schema
**So that** loop enforcement works without validation errors

## Description
The Stop hook's `transformStop()` method in `claude-code.js` returns `hookSpecificOutput` with `hookEventName: "Stop"`, but Claude Code's schema only supports `hookSpecificOutput` for PreToolUse, UserPromptSubmit, and PostToolUse events. This causes a JSON validation error every time the Stop hook blocks exit.

## Acceptance Criteria

### Scenario 1: Block exit (criteria incomplete)
**Given** the Stop hook needs to block exit because criteria are incomplete
**When** `transformStop()` returns the block response
**Then** it returns `{ continue: true, stopReason: "..." }` without `hookSpecificOutput`

### Scenario 2: Continue to next task in queue
**Given** a task completes and there's a next task in queue
**When** `transformStop()` returns the continue response
**Then** it returns `{ continue: true, systemMessage: "..." }` without `hookSpecificOutput`

### Scenario 3: Prompt before continuing
**Given** pauseBetweenTasks is enabled
**When** `transformStop()` returns the prompt response
**Then** it returns `{ continue: true, systemMessage: "..." }` without `hookSpecificOutput`

## Technical Notes
- **File**: `scripts/hooks/adapters/claude-code.js` lines 288-322
- Remove `hookSpecificOutput` from all 3 return paths in `transformStop()`
- The meaningful fields (`continue`, `stopReason`, `systemMessage`) are already top-level

## Complexity
Low - Remove invalid fields from 3 return statements
