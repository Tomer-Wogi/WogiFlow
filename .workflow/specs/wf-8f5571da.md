## Acceptance Criteria (behavior-level, one per finding)

1. **No cross-project path forgery** — Reading a phase file from a different project's path (e.g., `/tmp/evil/.claude/docs/phases/03-implement.md`) does NOT satisfy the phase-read gate for the current project. Only paths rooted in `PATHS.root` count.

2. **phase-reads.json recognized as known state** — The session-context hygiene system does NOT flag `phase-reads.json` as an unknown stale file. It is listed in `KNOWN_STATE_FILES`.

3. **No cross-session bleed** — When a session ends in `coding` phase with phase-reads recorded, the next session starts with a clean gate state. Either the file is cleared on session-end OR a session-scoped freshness check ignores stale records.

4. **clearPhaseReads uses top-level import** — `scripts/hooks/entry/claude-code/pre-tool-use.js` imports `clearPhaseReads` at the top of the file alongside `recordPhaseRead` and `checkPhaseReadGate`. No inline `require()` remains.

5. **Prompt claim matches enforcement** — The router's "Phase Execution" section accurately describes when the gate blocks and when it fails open. Either soften the "BLOCKS" language OR ensure phase transitions fire reliably before the gate becomes relevant.

6. **Continuation prompt phase map has Contents column** — `.claude/commands/wogi-start-continuation.md` phase map table includes the same Contents column as the router's version, giving the AI motivation to Read each file.

7. **Consumer impact check is self-contained** — `.claude/docs/phases/04-verify.md` Step 3.7 includes an inline sentence explaining the blast-radius file structure, so the AI can execute the check without needing 01-explore.md in context.

8. **Independent phaseReadGate config toggle** — `config.hooks.rules.phaseReadGate.enabled` exists in the config schema. When absent, falls back to `phaseGate.enabled` for backwards compatibility.

9. **Fast-path check includes phaseReadGate** — `flow-hook-status.js` `buildEnforcementFromConfig()` includes a `phaseReadGate` key. The `allGatesDisabled` check in pre-tool-use.js includes it in the fast-path.

10. **Robust path normalization** — The regex in `recordPhaseRead` handles nested `.claude` directories correctly (either via greedy match or `path.relative(PATHS.root, filePath)`).

11. **Race-safe state writes** — Either `recordPhaseRead` uses `withLockSync` for the read-modify-write cycle OR a code comment documents why locking is intentionally omitted.

12. **Continuation prompt inline refs point to phase files** — Inline gate references in `wogi-start-continuation.md` (e.g., "per Step 3.55") include "in the corresponding phase file" or equivalent direction to read the full procedure.

13. **Post-compact clears phase-reads** — After context compaction, `phase-reads.json` is cleared so the gate forces a re-read of the current phase's instructions in the new context.

14. **Defensive typeof check on command** — `toolInput.command` is verified as a string before `.trim()` is called in pre-tool-use.js line 220.

15. **Defensive import pattern documented** — A code comment in pre-tool-use.js explains why the phase-read gate uses try/catch fallback while phase-gate/routing-gate use direct require.

16. **Gate order documented** — A code comment notes that the phase-read gate depends on the phase gate's pre-filtering, which prevents it from firing before routing completes.
